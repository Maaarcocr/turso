### Notes

- Objects are tracked per database; `USE` switches the namespace, qualifiers naming the current database are removed, statements referencing another database's objects are filtered, and CREATE/DROP DATABASE are virtualized (a DROP ends every object generation in that database).
- Statements in `-- @session` blocks are skipped; objects they modify are not used by later candidates.
- Statements marked `-- @ignore`, `-- @regex`, `-- @wait*` or `-- @metacmp` are not emitted as candidates because MatrixOne masks or does not compare their output.
- Statements in `-- @bvt:issue` blocks are kept: they are skipped by MatrixOne's CI because of MatrixOne bugs, not because the SQL is invalid for MySQL.
- Setup is a dependency slice of the earlier statements of the same file: statements touching the objects a candidate reads, transitively, within the current generation of each object, plus all session statements (SET, transaction control, PREPARE). Every candidate uses setup_errors=drop.
- Queries are SELECT/WITH/TABLE/VALUES/EXECUTE, SHOW CREATE TABLE|VIEW, SHOW COLUMNS|INDEX|TABLES and DESCRIBE <table>. SHOW WARNINGS is emitted together with the statement it inspects. Non-query statements become candidates only when the source expects them to fail.
