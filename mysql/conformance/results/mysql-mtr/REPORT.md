### Notes

- Files are mysqltest programs read statically (see tools/import_mtr.py): `--source` includes are inlined, `let`/`eval`/`inc`/`dec`/`expr` with known values are evaluated, and `if`/`while` blocks run when their conditions are decidable (loops are unrolled). Statements in undecidable blocks, with unresolved variables or in mysqltest variable queries are not replayed, and candidates never depend on objects they touch.
- Candidate ids use the line of the top-level command (`--source`, `while`) plus an ordinal for statements it produces; provenance names the test file.
- Statements under --replace_*, --lowercase_result or --disable_result_log are not emitted as candidates because MTR masks their output.
- Each test runs in database `test`; its qualifier is removed.
- Only mysql-test/t and the suites collations, engines, funcs_1, funcs_2, gcol, gis, innodb_fts, innodb_gis, json, parts are imported; other suites test replication, NDB, plugins and components, storage-engine internals, server variables or system schemas.
- Setup is a dependency slice of the earlier statements of the same file: statements touching the objects a candidate reads, transitively, within the current generation of each object, plus all session statements (SET, transaction control, PREPARE). Every candidate uses setup_errors=drop.
- Queries are SELECT/WITH/TABLE/VALUES/EXECUTE, SHOW CREATE TABLE|VIEW, SHOW COLUMNS|INDEX|TABLES and DESCRIBE <table>. SHOW WARNINGS is emitted together with the statement it inspects. Non-query statements become candidates only when the source expects them to fail.
