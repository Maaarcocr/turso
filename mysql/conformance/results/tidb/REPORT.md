### Notes

- Each file starts in its own database (path with '/' replaced by '__'). Objects are tracked per database; `USE` switches the namespace, qualifiers naming the current database are removed, and statements referencing another database's objects are filtered, so every replayed slice runs in one database.
- Statements in non-default mysqltest connections are skipped; objects they modify are not used by later candidates.
- Statements with --replace_regex/--replace_column or inside --disable_result_log are not emitted as candidates because TiDB masks or ignores their output.
- TiDB's CLUSTERED/NONCLUSTERED primary key keyword is removed from CREATE/ALTER TABLE (InnoDB primary keys are always clustered); no other SQL is rewritten.
- Setup is a dependency slice of the earlier statements of the same file: statements touching the objects a candidate reads, transitively, within the current generation of each object, plus all session statements (SET, transaction control, PREPARE). Every candidate uses setup_errors=drop.
- Queries are SELECT/WITH/TABLE/VALUES/EXECUTE, SHOW CREATE TABLE|VIEW, SHOW COLUMNS|INDEX|TABLES and DESCRIBE <table>. SHOW WARNINGS is emitted together with the statement it inspects. Non-query statements become candidates only when the source expects them to fail.
